# 예선/본선 발표 PPT 권장 구성 목차(AI 서비스톤)

| 구분 | 내용 |
|---|---|
| 예시 | **슬라이드 1. 타이틀 (표지)**<br>- 내용: 대회명, 트랙명(AI 서비스톤), 팀명, 서비스명(프로젝트명), 발표자 및 팀원 성명 명시 |
| | **슬라이드 2. 서비스 개요 및 핵심 가치**<br>- 내용: 개발한 서비스의 한 줄 소개. 이 서비스가 유저에게 제공하는 가장 핵심적인 가치와 목적 정의 |
| | **슬라이드 3. 문제 배경 및 타깃 사용자**<br>- 내용: 서비스가 필요한 페르소나(타깃 사용자) 설정. 해당 사용자가 어떤 상황에서 심각한 불편(Pain Point)을 느끼는지 기술 |
| | **슬라이드 4. 서비스 주요 기능**<br>- 내용: 사용자가 실제로 이용할 수 있는 핵심 기능을 3가지 이상 아이콘과 타이틀 형태로 명확히 정리 |
| | **슬라이드 5. 사용자 이용 흐름 (User Flow)**<br>- 내용: 사용자가 서비스를 처음 접하고 회원가입 혹은 접속하여 최종 문제를 해결하기까지의 전체적인 UI/UX 흐름을 단계별(1단계 → 2단계 → 3단계 → 결과)로 도식화 |
| | **슬라이드 6. AI·SW 활용 기술 및 서비스 구조**<br>- 내용: 백엔드/프론트엔드 구조, 생성형 AI API 프롬프트 연계 방식, 활용한 개발 도구(노코드 툴, 웹/앱 빌더 등) 및 데이터 아키텍처 구조도 제시 |
| | **슬라이드 7. 프로토타입 시연 (하이라이트 슬라이드)**<br>- 내용: 구동 가능한 웹/앱 화면 캡처본 또는 GIF 애니메이션 배치<br>- 발표 팁: 실제 발표 시에는 이 부분에서 직접 브라우저나 에뮬레이터를 띄워 단계별 시연 시나리오에 맞춰 작동하는 모습을 실시간으로 시연 |
| | **슬라이드 8. 구현 범위 및 보완 계획**<br>- 내용: 현재 예선 단계에서 완료된 기능의 수와 미구현된 기능 명시. 시연 시 발생할 수 있는 오류나 제약 사항(접속 환경, 계정 등)을 솔직하게 밝히고 향후 개발 고도화 방향 제시 |
