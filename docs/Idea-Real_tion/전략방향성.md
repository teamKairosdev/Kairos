## ⛰️ Kairos 핵심 정체성 (반드시 각인)

> **"커리어의 총체적 추적, 종합적 활용 및 관리를 지원하는 종합 경력개발 에이전트 서비스 플랫폼"**

| 차원 | 비유 | 설명 |
|------|------|------|
| **지식 관리** | Notion / Obsidian | 사용자의 커리어 전 생애를 지식베이스로 구조화, 연결, 추적 |
| **소셜 네트워크** | Threads / X | 성장자극 SNS, 사회연결망 미니서비스 — 취업준비생-면접관-기업 연결 |
| **AI 에이전트** | 다중 에이전트 시스템 | 데이터 기반 분석, 예측, 조언 — MCP + CLI + 공공API 도구 활용 |

**AI 자소서 첨삭은 이 빙산의 일각에 불과하다.**  
전체는 **"커리어 오퍼레이팅 시스템 + 커리어 SNS"** 이며,  
이 문서의 모든 논의는 이 핵심 정체성을 전제로 한다.

---

## 1. 문제 인식: AI 자소서 서비스는 이미 죽은 시장

### 현실

| 서비스 | 강점 | 한계 |
|--------|------|------|
| ChatGPT / Claude / Gemini | 법용 라이팅 최강 | 도메인 특화 데이터 없음, 사용자 커리어 맥락 모름 |
| 자소설닷컴 / 합격자소서 | 한국 시장 점유 | 단순 첨삭, LLM 도입 전, 데이터 폐쇄적 |
| 기타 AI 취업 서비스 | UI 편리 | 전부 "프롬프트를 상품화"한 수준 |

**결론**: "AI가 이력서를 첨삭해줍니다"는 더 이상 차별점이 아니다.  
사용자는 ChatGPT에 "내 이력서 봐줘" 하면 된다.  
우리가 만들 서비스는 그 위에 **데이터 + 에이전트**라는 두 가지 레이어를 쌓아야 한다.

---

## 2. 차별화 전략: Agent + Data

### 2.1 데이터 레이어 (Moat)

Kairos가 독점적으로 보유/관리하는 데이터:

| 데이터 | 출처 | 활용 |
|--------|------|------|
| **면접 평가 결과** (점수 + 피드백 기록) | 자체 모의면접 | 성장 추적, 예측 분석 |
| **ATS 매칭 이력** (합/불 예측 데이터) | 자체 분석 | 채용 트렌드 인사이트 |
| **지원자-기업 매칭 데이터** | 검색 + 메시지 | 인재 추천 엔진 |
| **커뮤니티 데이터** (면접 후기, 평가) | 사용자 생성 | LLM fine-tuning 데이터 |
| **사용자 커리어 변화 추적** | 장기 사용 | 경력 예측 모델 |

**데이터가 쌓일수록 경쟁사 따라잡기 어려워짐** = 진입 장벽.

### 2.2 에이전트 레이어 (Orchestration)

단순 LLM 호출이 아니라 **다중 에이전트 오케스트레이션**:

```
사용자 입력
    │
    ├─→ 에이전트 A: 이력서 분석 (공공 API + CLI 도구 활용)
    ├─→ 에이전트 B: 채용 공고 수집 (MCP 서버로 기업 사이트 크롤링)
    ├─→ 에이전트 C: 면접 예상 질문 생성 (pgvector 검색 + LLM)
    └─→ 에이전트 D: 커리어 로드맵 제안 (사용자 히스토리 기반)
```

각 에이전트는 **도구(tool)를 가진다**:
- **MCP (Model Context Protocol)**: 기업 채용 사이트, 공공 API를 MCP 서버로 연결
- **CLI 도구**: 로컬 PDF 처리, 파일 변환, 데이터 파이프라인
- **공공 API**: 고용노동부, 워크넷, 산업인력공단 데이터
- **pgvector**: 시맨틱 검색으로 유사 케이스 참조

### 2.3 AI 조련 (Agent Conditioning)

단일 LLM에 의존하지 않고, **목적별 전용 에이전트를 지속적으로 개선**:

1. 각 에이전트는 `system prompt` + `tool set` + `few-shot examples` 로 구성
2. 사용자 피드백 루프로 지속 튜닝 (좋음/나쁨 평가)
3. A/B 테스트로 프롬프트/도구 조합 최적화
4. **결과가 좋은 에이전트 구성을 버전 관리** (자체 MCP 레지스트리)

## 3. 플랫폼 전략: Web + Desktop

### 3.1 Web (Nuxt 4 SPA)

- 빠른 프로토타이핑, 접근성
- 초기 사용자 유입 채널
- But: 브라우저 샌드박스 제약 (로컬 파일, 시스템 자원)

### 3.2 Desktop (Electron)

**반드시 Electron으로 가야 하는 이유**:

| 기능 | Web | Desktop |
|------|-----|---------|
| 로컬 PDF/파일 직접 읽기 | 파일 업로드 필요 | **네이티브 파일 접근** |
| 오프라인 AI (web-llm) | WebGPU 제약 | **로컬 GPU 활용** |
| CLI 도구 실행 | 불가능 | **subprocess 호출** |
| 시스템 트레이 / 알림 | 브라우저 탭 생명주기 | **OS 네이티브** |
| 데이터 보안 (민감한 이력서) | 클라우드 전송 | **로컬-first 가능** |

**추천 스택**: Electron + Vite (기존 Nuxt 코드를 Electron renderer로 재사용)

### 3.3 Electron 도입 로드맵

1. **Phase A**: Nuxt Web 앱 완성 (현재)
2. **Phase B**: `@nuxt/devtools` 기반 Electron 래퍼 (가벼운 통합)
3. **Phase C**: 네이티브 파일 접근 + CLI 통합
4. **Phase D**: 오프라인 AI (web-llm in Electon) + 시스템 트레이

## 4. 타케팅 (Targeting)

### 어떤 사용자에게 집중할 것인가

| 타겟 | 우선순위 | 근거 |
|------|----------|------|
| **경력 3-10년 이직 준비생** | 🔴 상 | AI 피드백 수용도 높음, 지불 의사 있음 |
| **대학교 4학년 취업 준비생** | 🔴 상 | 볼륨 큼, 바이럴 효과 |
| **HR / 면접관 (기업)** | 🟡 중 | B2B 수익 모델, 제품 완성도 필요 |
| **고졸 취업 준비생** | 🟢 하 | 시장 크기 작음, 지원 리소스 한계 |

### 가치 제안 (Positioning)

> "Kairos는 **당신의 커리어 전 생애**를  
> **AI 에이전트**가 분석·예측·조언하고,  
> **SNS**가 성장을 자극하며,  
> **지식베이스(Notion/Obsidian)**가 모든 기록을 구조화하는  
> **종합 경력개발 에이전트 서비스 플랫폼**입니다."

→ 절대 "AI 자소서 첨삭 서비스"라고 하면 안 됨.  
→ 자소서 첨삭은 빙산의 일각, 전체는 커리어 OS + 커리어 SNS.

## 5. 디자인 원칙

### 5.1 UX 철학: Trust (신뢰)

취업 데이터는 개인에게 가장 민감한 정보 중 하나.

| 원칙 | 설명 |
|------|------|
| **투명성** | AI 판단 근거를 항상 표시 (confidence score, 참조 데이터) |
| **컨트롤** | 사용자가 데이터 공유 범위를 세밀하게 제어 |
| **일관성** | Glassmorphism + Kairos Design System 일관 유지 |
| **속도** | 모든 화면 1초 이내 로딩 (SSE 스트리밍도 skeleton UI 필수) |

### 5.2 시각 디자인

- **현재 방향 유지**: Dark Glassmorphism (어두운 공간에서 장시간 사용)
- **개선 필요**: 접근성 (WCAG AA 대비), 반응형 태블릿/모바일
- **Electron**: Native 타이틀바 → Custom titlebar 동기화

## 6. 숲을 보라 (Forest, not Trees)

멘토 분들이 "숲을 봐야 한다"는 말의 의미:

### 단기 (0-6개월) — 나무 심기
- 현재 SPA 데모 → 실서비스 전환 (P1-P3: 테스트/CI/CD/모니터링)
- 핵심 루프 완성: 이력서 → 면접 → ATS → 피드백
- 1명의 사용자가 30분 동안 가치를 느끼게 하는 데 집중

### 중기 (6-12개월) — 숲 조성
- MCP 서버로 외부 데이터 연결 (공공 API, 기업 채용 사이트)
- Electron 데스크탑 앱 출시
- 커뮤니티 → 데이터 모이기 시작 → 네트워크 효과
- B2B 기업용 인터뷰 관리 패널

### 장기 (12-24개월) — 생태계
- AI 에이전트 마켓플레이스 (MCP 기반 사용자 제작 에이전트)
- 커리어 예측 엔진 (데이터 기반 퇴사/이직/승진 예측)
- **SNS 효과** — Threads/X-like 성장자극 플랫폼 기능 (피드, 팔로우, 반응, 커리어 인증)
- 글로벌 확장 (i18n, 해외 채용 시장)

## 7. 내 분석 (냉철 이성)

### 강점 (지금 잘하고 있는 것)
- 기술 스택은 최신, Phase 0-8 완료로 기술 부채 없음
- pgvector + AI SDK + Better Auth 조합은 확장성 좋음
- SSE 스트리밍, Glassmorphism 등 UX 품질 양호

### 약점 (냉정히 볼 것)
- **Zero tests** — 가장 큰 위험. AI 응답이 변경되면 기도메타
- **No monitoring** — 오류를 알 방법이 없음
- **SPA-only** — SEO 불가, 로컬-first가 아님
- **Single LLM dependency** — 모델 API 장애 = 서비스 장애
- **데이터가 없다** — 현재 DB는 빈 껍데기. 데이터 축적이 시작되지 않음

### 가장 위험한 가정
> "사용자가 이력서를 등록하고 AI 분석을 받을 것이다"

- 사용자 행동: 대부분 이력서 PDF를 들고 다니지만, **서비스에 업로드하지 않는다**
- 완화: 로컬 파일 드래그 → 브라우저에서만 처리 (클라우드 전송 없음) 신뢰 확보
- 완화: Google Drive / OneDrive / Notion 연동 → 진입 장벽 낮춤

### 방향성에 대한 최종 판단

| 주제 | 판단 | 근거 |
|------|------|------|
| AI 첨삭 서비스? | ❌ 버려라 | 경쟁사 수백 개, 차별화 불가 |
| Agent + Data? | ✅ 맞다 | 장기적 moat 형성 유일한 경로 |
| Electron? | ✅ 필요하다 | 로컬 데이터 + CLI + WebGPU offline |
| MCP? | ✅ 투자할 가치 | 업계 표준으로 떠오르는 중 |
| Web-first? | ✅ 계속 | 초기 사용자 획득 비용 최소 |
| B2B 먼저? | ❌ B2C 먼저 | B2B는 제품-시장 fit 증명 후 |

## 8. 즉시 실행 액션

우선 MCP 서버 프로토타이핑부터 시작. 공공 API 하나만 연결해도 의미 있다.

| 액션 | 기간 | 담당 |
|------|------|------|
| 공공 채용 API 조사 (워크넷, 고용24) | 1일 | 기획 |
| MCP 서버 PoC (워크넷 채용공고 검색) | 3일 | 개발 |
| 로컬 PDF 처리 Electron PoC | 5일 | 개발 |
| 사용자 테스트 5명 (현재 SPA로) | 7일 | 기획+개발 |

> **이 문서의 결론**:  
> Kairos는 AI 자소서 서비스가 아니다.  
> **커리어 OS (Notion/Obsidian) + 커리어 SNS (Threads/X) + AI Agent Orchestration**  
> 이 세 가지 축이 진정한 정체성이며 차별화 전략이다.  
> 단순 첨삭 기능은 빙산의 일각 — 전체를 봐야 한다.  
> 그리고 가장 시급한 것은 **테스트 코드와 모니터링**이다 (기능보다 기반이 먼저).
