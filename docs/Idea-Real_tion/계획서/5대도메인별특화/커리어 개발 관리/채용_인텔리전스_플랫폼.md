## 1. 왜 이 기능이 필요한가

### 현재 채용 시장의 구조적 거짓말

```
[채용공고의 진실]

기업이 공고에 쓰는 것:              실제 현실:
─────────────────────────          ─────────────────────────
"수평적 조직 문화"           →     팀장이 모든 걸 결정
"워라밸 보장"                →     야근이 기본값
"성장 지원"                  →     교육비 신청 불가
"도전적인 업무환경"          →     레거시 코드 유지보수만
"글로벌 비즈니스"            →     엑셀 정리
"경쟁력 있는 연봉"           →     신입 최저 연봉
"스타트업 DNA"               →     대표 1인 독재 체제

[이력서의 진실]

지원자가 이력서에 쓰는 것:          실제 현실:
─────────────────────────          ─────────────────────────
"프로젝트 주도"              →     팀장이 시킨 대로 했음
"성과 40% 향상"              →     측정 기준이 자의적
"글로벌 커뮤니케이션"        →     영문 이메일 2번 써봄
"리더십 발휘"                →     팀장이 없을 때 회의 진행
"AI 활용 능력"               →     ChatGPT를 써봤음
```

### 현재 채용 플랫폼의 한계

| 플랫폼 | 강점 | 치명적 한계 |
|--------|------|-----------|
| **잡코리아** | 채용공고 많음 | 공고의 진위 검증 없음. 기업 리뷰 없음 |
| **사람인** | 이력서 관리 | 깊이 있는 기업 정보 없음 |
| **LinkedIn** | 네트워크 | 한국 시장 활성화 미약. 자기 홍보 일색 |
| **Glassdoor** | 기업 리뷰 | 한국 기업 데이터 빈약. 리뷰 신뢰도 의문 |
| **블라인드** | 익명 후기 | 채용 기능 없음. 기업 정보 구조화 미약 |
| **Reddit** | 심층 토론 | 한국 채용 전문 커뮤니티 없음 |

### Kairos가 만드는 새로운 레이어

> **기존**: 채용공고 → 지원 → 합격/탈락 (블랙박스)  
> **Kairos**: 채용공고 → **기업 메타 분석** → **지원 전략 설계** → **면접 인텔리전스** → 합격

> **기존**: 이력서 → ATS 필터 → 면접 (블랙박스)  
> **Kairos**: 이력서 → **후보자 메타 분석** → **진짜 역량 발견** → **적합 포지션 매칭** → 채용

### 2.2 정보 흐름

```
[지원자 → 기업 방향]
지원자가 Kairos에서 기업 검색
    → 공식 채용공고 파싱
    → 재직자 익명 후기 집계
    → 면접 경험 데이터베이스
    → AI 문화·복지 진실도 분석
    → 실제 연봉 분포 (익명 집계)
    → 지원 전략 + 면접 예측 질문
    → 합격 가능성 스코어

[기업 → 지원자 방향]
기업 HR이 Kairos에서 인재 검색
    → 이력서 + pgvector 검색
    → AI 역량 신뢰도 분석
    → 커뮤니티 활동 패턴 (동의한 경우)
    → 면접 시뮬레이션 결과 (동의한 경우)
    → 문화 적합도 예측 스코어
    → 인재 네트워크 연결 제안
```

### 3.5 면접 경험 데이터베이스

```

필터: 백엔드 | 최근 6개월 | 신입~2년차

───────────────────────────────────────────────────
 합격 후기 #1 (2025.06.15, 익명)
  전형: 코테(통과) → 1차 기술(통과) → 2차 임원(합격)
  1차 질문:
    Q. "DB 인덱스가 왜 빠른가요? B-Tree 기준으로 설명해주세요"
    Q. "N+1 문제 경험하셨나요? 어떻게 해결하셨나요?"
    Q. "RESTful API 설계 시 URL 구조 어떻게 잡으시나요?"
  2차 질문:
    Q. "5년 후 어떤 개발자가 되고 싶으세요?"
    Q. "팀에서 의견 충돌이 있을 때 어떻게 해결하시나요?"
  
  합격 비결: "기술 질문에 '왜'를 설명하는 연습이 효과적이었음.
              단순히 어떻게 구현했는지보다 왜 그 방법을 선택했는지"

───────────────────────────────────────────────────
 탈락 후기 #2 (2025.05.22, 익명)
  탈락 단계: 1차 기술면접
  느낀 탈락 이유: "Redis vs Memcached 차이를 물어봤는데

    skillMatch: number    // 기술 스킬 매칭 (40%)
    cultureMatch: number  // 문화 적합도 (25%)
    salaryExpect: number  // 연봉 기대치 부합 (15%)
    careerPath: number    // 커리어 성장 방향 일치 (20%)
  }
}

async function calculateMatchScore(
  candidateProfile: CandidateProfile,
  companyProfile: CompanyProfile,
  jobPosting: JobPosting
): Promise<MatchScore> {
  
  // 1. 스킬 매칭 (알고리즘)
  const requiredSkills = extractSkills(jobPosting.requirements)
  const candidateSkills = candidateProfile.skills
  const skillMatch = calculateJaccardSimilarity(requiredSkills, candidateSkills)
  
  // 2. 문화 적합도 (pgvector)
  const companyCultureVector = await getEmbedding(companyProfile.cultureKeywords)
  const candidateStyleVector = await getEmbedding(candidateProfile.workStyle)
  const cultureMatch = cosineSimilarity(companyCultureVector, candidateStyleVector)
  
  // 3. 연봉 기대치 (알고리즘)
  const companyRange = companyProfile.salaryRange[jobPosting.level]
  const candidateExpect = candidateProfile.salaryExpectation
  const salaryMatch = calculateRangeOverlap(companyRange, candidateExpect)
  
  // 4. 커리어 패스 (LLM — 캐시 활용)
  const careerMatch = await getCachedOrGenerate(
    `career_match_${candidateProfile.id}_${companyProfile.id}`,
    () => evaluateCareerPathMatch(candidateProfile, companyProfile)
  )
  
  return {
    total: Math.round(
      skillMatch * 40 + cultureMatch * 25 + 
      salaryMatch * 15 + careerMatch * 20
    ),
    breakdown: { skillMatch, cultureMatch, salaryMatch, careerPath: careerMatch }
  }
}
```

[기존 플랫폼의 한계 vs Kairos]
