## 1. 워크플로우 vs 자율형 에이전트

> 출처: 해피톡 아키텍쳐 구축기 — Anthropic 에이전트 패턴 분류

### 1.1 핵심 차이

```
[결정론적 워크플로우]           [자율형 에이전트]
─────────────────────          ─────────────────────
개발자가 흐름을 고정            LLM이 스스로 흐름을 결정
예측 가능, 안전                유연, 강력, 위험
단순 반복 작업에 최적           복잡하고 개방적 문제에 최적
비용 예측 가능                 비용 예측 어려움
재현 가능                     출력이 매번 다를 수 있음
```

### 1.2 Kairos의 선택 원칙

**해피톡의 교훈**: 처음부터 자율 에이전트로 가되, **가드레일 피드백 루프**로 안전망을 친다.

**Kairos 적용 원칙**:

| 기능 | 선택 | 이유 |
|------|------|------|
| 이력서 고도화 | 워크플로우 (Evaluator-Optimizer) | 결과 품질 예측 필요, 재현성 중요 |
| ATS 분석 | 워크플로우 (Prompt Chaining) | 구조화된 작업, 빠른 응답 필요 |
| AI 모의 면접 | 자율 에이전트 (ReAct) | 대화 흐름이 매번 달라야 함 |
| 커리어 어시스턴트 | 자율 에이전트 (Orchestrator-Workers) | 다양한 도구 조합 필요 |
| 채용공고 수집·분석 | 워크플로우 (병렬화) | 대량 처리, 일관성 필요 |
| 지원 전략 생성 | 하이브리드 | Plan-and-Execute + Reflection |

## 2. 결정론적 워크플로우 패턴

### 2.1 프롬프트 체이닝 (Prompt Chaining)

> "이전 LLM 출력이 다음 LLM 입력이 된다"

```
[Kairos 이력서 ATS 분석 체인]

Step 1: JD 파싱
LLM-1 입력: "이 채용공고에서 필수/우대 스킬을 JSON으로 추출하라"
LLM-1 출력: { required: [...], preferred: [...] }
                │
                ▼
Step 2: 이력서 스킬 매핑
LLM-2 입력: { jdSkills } + "이 이력서에서 동일/유사 스킬을 찾아라"
LLM-2 출력: { matched: [...], missing: [...], similar: [...] }
                │
                ▼
Step 3: 개선 제안 생성
LLM-3 입력: { missing } + "각 누락 스킬에 대한 이력서 개선 문장을 작성하라"
LLM-3 출력: { suggestions: [...] }
```

**구현 코드 패턴:**

```typescript
// server/services/ats/chain.ts
async function runATSChain(resumeText: string, jdText: string) {
  // Step 1: JD 분석 (저비용 모델)
  const jdAnalysis = await generateObject({
    model: anthropic('claude-3-5-haiku-20241022'),
    schema: jdAnalysisSchema,
    system: JD_PARSER_SYSTEM_PROMPT,
    prompt: `채용공고:\n${jdText}`,
    experimental_providerOptions: {
      anthropic: { cacheControl: { type: 'ephemeral' } }
    }
  })

  // Step 2: 매칭 분석 (알고리즘 우선, LLM 보완)
  const algorithmMatch = calculateKeywordMatch(resumeText, jdAnalysis.object)
  const semanticMatch = await getSemanticSimilarity(resumeText, jdText) // pgvector

  // Step 3: 개선 제안 (중간 모델)
  const suggestions = await generateText({
    model: anthropic('claude-3-5-sonnet-20241022'),
    system: ATS_SUGGESTION_SYSTEM_PROMPT,
    prompt: buildSuggestionPrompt(algorithmMatch, semanticMatch),
  })

  return { algorithmMatch, semanticMatch, suggestions }
}
```

**적용 기능**: ATS 분석, 이력서 섹션별 평가, Q&A 플래시카드 생성

### 2.2 라우팅 (Routing)

> "입력을 분류하여 적합한 전문 프롬프트로 라우팅한다"

```
[Kairos 커리어 어시스턴트 라우팅]

사용자 입력
    │
    ▼
[분류기 LLM]
"이 요청은 어떤 카테고리인가?"
    │
    ├── "이력서 관련" → 이력서 전문 에이전트
    ├── "면접 관련"   → 면접 코치 에이전트
    ├── "채용공고"    → JD 분석 에이전트
    ├── "커리어 전략" → 전략 수립 에이전트
    └── "일반 질문"   → 범용 커리어 어시스턴트
```

**구현 패턴:**

```typescript
// server/services/router.ts
const INTENT_CLASSIFIER_PROMPT = `
사용자의 메시지를 다음 카테고리 중 하나로 분류하라:
RESUME | INTERVIEW | JD_ANALYSIS | CAREER_STRATEGY | GENERAL

JSON으로만 응답: { "intent": "RESUME", "confidence": 0.95 }
`

async function routeToAgent(userMessage: string, context: UserContext) {
  const { object } = await generateObject({
    model: anthropic('claude-3-5-haiku-20241022'), // 분류는 저비용
    schema: intentSchema,
    system: INTENT_CLASSIFIER_PROMPT,
    prompt: userMessage,
  })

  switch (object.intent) {
    case 'RESUME':      return resumeAgent(userMessage, context)
    case 'INTERVIEW':   return interviewAgent(userMessage, context)
    case 'JD_ANALYSIS': return jdAnalysisAgent(userMessage, context)
    case 'CAREER_STRATEGY': return strategyAgent(userMessage, context)
    default:            return generalAssistant(userMessage, context)
  }
}
```

### 2.3 병렬화 (Parallelization)

> "여러 LLM을 동시에 실행하여 속도를 높이거나 관점을 다양화한다"

```
[Kairos 이력서 다각 평가 병렬화]

이력서 텍스트 입력
    │
    ├──→ [ATS 관점 평가] ──────────────┐
    ├──→ [채용담당자 관점 평가] ─────────┤
    ├──→ [팀장 관점 평가] ────────────── ├──→ [종합 점수 집계]
    └──→ [경쟁자 관점 비교] ────────────┘
         (모두 Promise.all로 병렬 실행)
```

**구현 패턴:**

```typescript
// server/services/resume/multiPerspective.ts
async function evaluateFromMultiplePerspectives(resumeText: string) {
  const [atsEval, hrEval, managerEval] = await Promise.all([
    evaluateAsATS(resumeText),
    evaluateAsHR(resumeText),
    evaluateAsHiringManager(resumeText),
  ])

  return aggregateEvaluations([atsEval, hrEval, managerEval])
}
```

**적용 기능**: 이력서 다각 평가, 채용공고 대량 수집 처리, 여러 기업 동시 분석

### 2.4 평가자-최적화자 (Evaluator-Optimizer)

> 해피톡 블로그의 핵심 패턴. "생성 → 평가 → 조건부 재생성" 루프

```
[Kairos 이력서 3단계 고도화 파이프라인]

                    ┌──────────────────────────────┐
                    │                              │
이력서 입력  ──→  [Generator LLM]  ──→  [Evaluator LLM]
                    ↑                      │
                    │               품질 기준 통과?
                    │                      │
                    └── NO (재생성) ────────┘
                                           │
                                    YES (출력)
                                           │
                                    최종 이력서
```

**Kairos 품질 기준:**

```typescript
interface EvaluationCriteria {
  hasQuantitativeMetrics: boolean    // 수치 포함 여부
  hasActiveVoice: boolean           // 능동태 사용
  noAIPatterns: boolean             // AI 문체 패턴 없음
  atsKeywordDensity: number         // 키워드 밀도 > 0.15
  overallScore: number              // 종합 점수 >= 75
}

async function runEvaluatorOptimizer(
  resumeText: string,
  maxIterations: number = 3
): Promise<string> {
  let currentResume = resumeText
  let iteration = 0

  while (iteration < maxIterations) {
    // Step 1: Generate (개선 시도)
    const improved = await generateText({
      model: anthropic('claude-opus-4-5'),
      system: RESUME_GENERATOR_SYSTEM_PROMPT,
      prompt: buildImprovementPrompt(currentResume, iteration),
    })

    // Step 2: Evaluate (품질 평가)
    const evaluation = await evaluateResume(improved.text)

    // Step 3: 기준 통과 시 반환
    if (meetsQualityCriteria(evaluation)) {
      return improved.text
    }

    // 기준 미통과 시 재생성 (피드백 포함)
    currentResume = addEvaluationFeedback(improved.text, evaluation)
    iteration++
  }

  return currentResume // maxIterations 도달 시 최선 반환
}
```

## 3. 자율 에이전트 패턴

### 3.1 ReAct — 자율 루프의 정석

> Reasoning(추론) + Acting(행동) 반복 루프  
> 해피톡이 채택한 핵심 패턴

```
[Kairos AI 면접관 ReAct 루프]

사용자 답변 입력
    │
    ▼
[Reason]: "이 답변에서 무엇을 평가해야 하나?
           STAR 구조인가? 수치가 있나? 논리적인가?"
    │
    ▼
[Act]: 평가 도구 호출
  - evaluate_star_structure(answer)
  - check_technical_accuracy(answer, jobRole)
  - assess_communication_clarity(answer)
    │
    ▼
[Observe]: 평가 결과 확인
    │
    ▼
[Reason]: "다음 질문을 어떻게 설계할까?
           심화 질문? 전환 질문? 확인 질문?"
    │
    ▼
[Act]: 다음 질문 생성 + SSE로 스트리밍
    │
    ▼
[Loop] 면접 종료 조건까지 반복
```

**구현 패턴 (AI SDK v7):**

```typescript
// server/api/interview/[sessionId].post.ts
export default defineEventHandler(async (event) => {
  const { userAnswer, sessionId } = await readBody(event)
  const session = await getInterviewSession(sessionId)

  return streamSSE(event, async (stream) => {
    const result = await streamText({
      model: anthropic('claude-opus-4-5'),
      system: buildInterviewerSystemPrompt(session.jobRole, session.level),
      messages: session.history,
      tools: {
        evaluateAnswer: tool({
          description: '지원자 답변을 STAR 기준으로 평가한다',
          parameters: z.object({ answer: z.string(), criteria: z.array(z.string()) }),
          execute: async ({ answer, criteria }) => evaluateSTAR(answer, criteria),
        }),
        generateFollowUp: tool({
          description: '다음 면접 질문을 생성한다',
          parameters: z.object({ questionType: z.enum(['DEEPDIVE', 'PIVOT', 'CLARIFY']) }),
          execute: async ({ questionType }) => generateQuestion(session, questionType),
        }),
        endInterview: tool({
          description: '면접을 종료하고 종합 피드백을 생성한다',
          parameters: z.object({ reason: z.string() }),
          execute: async ({ reason }) => generateFinalFeedback(session),
        }),
      },
      maxSteps: 10, // 무한 루프 방지
    })

    for await (const chunk of result.textStream) {
      await stream.push({ data: chunk, event: 'text' })
    }
  })
})
```

### 3.2 계획 후 실행 (Plan-and-Execute)

> "먼저 전체 계획을 세우고, 단계별로 실행한다"

```
[Kairos 커리어 전략 수립 에이전트]

사용자 목표 입력: "6개월 안에 카카오 백엔드로 이직"
    │
    ▼
[Planner LLM]: 전체 계획 수립
  {
    "plan": [
      { "step": 1, "task": "현재 이력서 ATS 분석", "tool": "ats_analyze" },
      { "step": 2, "task": "부족 스킬 파악", "tool": "skill_gap_analyze" },
      { "step": 3, "task": "학습 로드맵 생성", "tool": "learning_roadmap" },
      { "step": 4, "task": "목표 기업 채용공고 수집", "tool": "job_scrape" },
      { "step": 5, "task": "지원 전략 문서화", "tool": "strategy_write" }

  }
    │
    ▼
[Executor]: 각 단계 순서대로 실행
  → 각 단계 완료 후 SSE로 진행 상황 전송
  → 사용자가 중간에 방향 수정 가능

    ▼

```

### 3.3 리플렉션 (Reflection)

> "자신의 출력을 스스로 검토하고 개선한다"  
> 해피톡의 가드레일 핵심 패턴

```
[Kairos AI 휴머나이저 Reflection 루프]

AI 문장 입력
    │
    ▼
[Generator]: 인간적 문장으로 변환
    │
    ▼
[Critic (Reflection)]:
  "이 문장이 여전히 AI 같은가?"
  체크리스트:
  - "~했습니다" 패턴 과다 사용?
  - "또한", "더불어" 반복?
  - 지나치게 완벽한 구조?
  - 수동태 과다?
    │
    ├── 문제 없음 → 출력
    │
    └── 문제 있음 → [Generator]에 피드백 전달 후 재생성
```

**구현 패턴:**

```typescript
// server/services/humanizer/reflection.ts
async function humanizeWithReflection(aiText: string, maxTurns = 2): Promise<string> {
  let text = aiText

  for (let turn = 0; turn < maxTurns; turn++) {
    // 1. 생성
    const humanized = await generateText({
      model: anthropic('claude-3-5-sonnet-20241022'),
      system: HUMANIZER_SYSTEM_PROMPT,
      prompt: `다음 AI 문장을 자연스러운 인간 문체로 변환하라:\n${text}`,
    })

    // 2. 자가 비평 (Reflection)
    const critique = await generateObject({
      model: anthropic('claude-3-5-haiku-20241022'), // 비평은 저비용
      schema: humanizationCritiqueSchema,
      system: `당신은 AI 탐지 전문가입니다. 다음 텍스트가 AI가 작성한 것인지 판별하라.`,
      prompt: humanized.text,
    })

    if (critique.object.aiScore < 30) {
      return humanized.text  // 인간적으로 충분히 자연스러움
    }

    // 피드백을 포함해 다음 턴 준비
    text = `${humanized.text}\n\n[비평: ${critique.object.feedback}]`
  }

  return text
}
```

### 3.4 오케스트레이터-워커 (Orchestrator-Workers)

> "중앙 오케스트레이터가 전문 워커에게 작업을 위임한다"  
> Kairos의 핵심 에이전트 구조

```
[Kairos 커리어 오케스트레이터]

사용자: "삼성 소프트웨어 직무에 지원하고 싶어요. 뭐부터 해야 해요?"
    │
    ▼
[🧠 오케스트레이터 LLM]
"이 요청은 다음 워커들의 협력이 필요하다:
 1. JD 수집 워커 → 삼성 현재 채용공고 수집
 2. ATS 분석 워커 → 사용자 이력서와 매칭
 3. 스킬갭 분석 워커 → 부족한 것 파악
 4. 전략 수립 워커 → 구체적 행동 계획 작성"
    │
    ├──→ [📋 JD 수집 워커]     → 삼성 최신 채용공고 5개 수집
    ├──→ [🎯 ATS 분석 워커]    → 이력서 vs 공고 매칭 분석
    ├──→ [🔍 스킬갭 워커]      → 부족 스킬 3개 도출
    └──→ [📊 전략 수립 워커]   → 3개월 준비 플랜 작성
              │
              ▼
    [오케스트레이터]: 워커 결과 통합 → 사용자에게 전달
```

## 4. Kairos 전체 에이전트 구조 설계

```
┌─────────────────────────────────────────────────────────────────────┐
│                       KAIROS AGENT SYSTEM                           │
│                                                                     │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │                   Entry Layer                                │   │
│  │  사용자 요청 → [Intent Router] → 적합한 에이전트 선택       │   │
│  └──────────────────────────┬──────────────────────────────────┘   │
│                             │                                       │
│         ┌───────────────────┼───────────────────┐                  │
```

```typescript
// server/lib/modelRouter.ts

type TaskComplexity = 'TRIVIAL' | 'SIMPLE' | 'COMPLEX' | 'CRITICAL'

function selectModel(complexity: TaskComplexity, costSensitive: boolean) {
  // 비용 vs 품질 트레이드오프 매트릭스
  const modelMatrix = {
    TRIVIAL:  'claude-3-5-haiku-20241022',   // 분류, 라우팅, 간단 추출
    SIMPLE:   'claude-3-5-sonnet-20241022',  // ATS 분석, 면접 질문
    COMPLEX:  'claude-opus-4-5',             // 이력서 고도화, 전략 수립
    CRITICAL: 'claude-opus-4-5',             // 최종 출력, 민감한 피드백
  }

  // 비용 절감 모드: 한 단계 낮은 모델
  if (costSensitive) {
    const downgrade = { COMPLEX: 'SIMPLE', SIMPLE: 'TRIVIAL', TRIVIAL: 'TRIVIAL' }
    return modelMatrix[downgrade[complexity] || complexity]
  }

  return modelMatrix[complexity]
}

// 사용자 플랜별 모델 차등 제공
function getModelForUser(complexity: TaskComplexity, userPlan: 'FREE' | 'PRO' | 'TEAM') {
  if (userPlan === 'FREE' && complexity === 'CRITICAL') {
    return modelMatrix['SIMPLE']  // 무료는 중간 모델
  }
  return selectModel(complexity, userPlan === 'FREE')
}
```

```typescript
    retryDelay: 1_000,
    costLimit: 0.05,

async function runWithHarness<T>(
  fn: () => Promise<T>,
  config: HarnessConfig
): Promise<T> {
  for (let attempt = 0; attempt <= config.maxRetries; attempt++) {
    try {
      const result = await Promise.race([
        fn(),
        new Promise<never>((_, reject) =>
          setTimeout(() => reject(new Error('TIMEOUT')), config.timeout)
        ),
      ])
      return result
    } catch (err) {
      if (attempt === config.maxRetries) throw err
      await sleep(config.retryDelay * (attempt + 1)) // 지수 백오프
    }
  }
  throw new Error('Max retries exceeded')
}
```

```typescript
// server/lib/costControl.ts

class CostController {
  private redis: Redis

  async checkAndCharge(userId: string, estimatedCost: number): Promise<boolean> {
    const key = `cost:${userId}:${getCurrentMonth()}`
    const current = parseFloat(await this.redis.get(key) || '0')
    const limit = await this.getUserPlanLimit(userId)

    if (current + estimatedCost > limit) {
      throw new QuotaExceededError(`월간 한도 초과: ${current}/${limit} USD`)
    }

    await this.redis.incrbyfloat(key, estimatedCost)
    await this.redis.expire(key, 60 * 60 * 24 * 32) // 32일
    return true
  }

  estimateCost(model: string, inputTokens: number, outputTokens: number): number {
    const pricing = {
      'claude-3-5-haiku-20241022':  { in: 0.001, out: 0.005 },
      'claude-3-5-sonnet-20241022': { in: 0.003, out: 0.015 },
      'claude-opus-4-5':            { in: 0.015, out: 0.075 },
    }
    const p = pricing[model]
    return (inputTokens * p.in + outputTokens * p.out) / 1000
  }
}
```

```typescript
  context: string,
  model: string,
  reserveForOutput: number = 4_000
```

## 7. Loop Engineering

> "피드백 루프를 어떻게 설계하면 AI 출력 품질이 높아지는가"  
> 해피톡의 핵심 교훈: 루프 없이는 환각과 품질 저하를 막을 수 없다

### 7.1 이력서 고도화 루프

```
[Evaluator-Optimizer Loop]

입력: 이력서 원본
    │
    ▼ (최대 3회 반복)

│         │                               │

│    YES ─┤ NO                            │
│         │  │                            │

          │
```

### 7.2 면접 대화 루프

```
[ReAct Loop — 면접 세션]

초기화: 직무, 난이도, 지원자 이력서
    │
    ▼
[루프 시작]
  Reason:
    - 지금까지 평가 점수 확인
    - 아직 다루지 않은 평가 영역 파악
    - 지원자 답변 패턴 분석

    - 면접 질문 생성 or 팔로우업

  Observe:
    - 지원자 답변 수신
    - 답변 평가 도구 호출
    - 평가 점수 업데이트
    │
    ▼

  - 할당 질문 수 완료? → 종합 피드백 생성
  - 지원자 종료 요청? → 즉시 종료
  - 최대 시간 초과?   → 자동 종료
    │
    ▼
[최종 평가 루프]
  - 전체 세션 데이터 → Evaluator-Optimizer → 종합 피드백
```

### 7.3 가드레일 루프 (해피톡 핵심 교훈 적용)

```typescript
// server/lib/guardrail.ts

interface GuardrailResult {
  passed: boolean
  issues: string[]
  severity: 'LOW' | 'MEDIUM' | 'HIGH'
}

async function runGuardrail(output: string, context: GuardrailContext): Promise<string> {
  // 1. 빠른 규칙 기반 체크 (알고리즘 — 즉시)
  const ruleCheck = checkRules(output, context)
  if (ruleCheck.severity === 'HIGH') {
    return await regenerate(output, ruleCheck.issues, context)
  }

  // 2. LLM 기반 품질 검사 (비동기 — 사후 처리)
  // 해피톡 패턴: 사후 가드레일 (응답 전달 후 검증)
  queueGuardrailCheck(output, context, async (result) => {
    if (!result.passed) {
      await flagForReview(output, result.issues)
      await notifyUser('응답이 검토 중입니다')
    }
  })

  return output  // 먼저 전달, 검증은 사후
}

// 검사 항목
function checkRules(output: string, context: GuardrailContext): GuardrailResult {
  const issues: string[] = []

  // 규칙 1: 개인정보 노출 방지
  if (containsPII(output)) issues.push('PII_DETECTED')

  // 규칙 2: 환각 감지 (존재하지 않는 기업명, 날짜 등)
  if (hasHallucination(output, context)) issues.push('HALLUCINATION_DETECTED')

  // 규칙 3: 도구 오용 방지 (해피톡이 겪은 문제)
  if (hasInvalidToolCall(output)) issues.push('INVALID_TOOL_USE')

  // 규칙 4: 부적절한 조언 (법적·의료적·재정적 조언 금지)
  if (containsProhibitedAdvice(output)) issues.push('PROHIBITED_ADVICE')

  return {
    passed: issues.length === 0,
    issues,
    severity: getSeverity(issues)
  }
}
```

## 9. 가드레일 아키텍쳐

> 해피톡이 자율 에이전트 운용에서 가장 크게 배운 것:  
> **"자율성에는 반드시 안전벨트가 필요하다"**

### 9.1 Kairos 가드레일 계층

```
[Kairos 4계층 가드레일]

Layer 1: 입력 가드레일 (사전 — 즉각)
  - 사용자 입력 길이 제한 (토큰 낭비 방지)
  - 명백한 부적절 입력 차단 (욕설, 개인정보)
  - Rate Limiting (Upstash Redis)

Layer 2: 컨텍스트 가드레일 (구성 시)
  - 프롬프트 인젝션 방지
  - 시스템 프롬프트 무결성 검증
  - 도구 호출 권한 범위 제한

Layer 3: 출력 가드레일 (사후 — 비동기)
  해피톡 패턴: 먼저 전달, 사후 검증
  - 환각 감지 (사실 오류 체크)
  - PII 노출 방지
  - 부적절한 커리어 조언 차단
  - 도구 오용 감지

Layer 4: 피드백 루프 가드레일 (반복 시)
  - 루프 무한 반복 방지 (MAX_ITERATIONS)
  - 비용 임계치 초과 방지
  - 타임아웃 강제 종료
```

### 9.2 실시간 vs 사후 처리 전략 (해피톡 고민 적용)

```
[해피톡이 겪은 딜레마 → Kairos 해결책]

문제: 가드레일 검증에 시간이 걸림 → 사용자 경험 저하
해결: 사후 가드레일 패턴 채택

흐름:
  1. 에이전트 출력 생성 (SSE 스트리밍)
  2. 출력 즉시 사용자에게 전달 (지연 없음)
  3. 비동기로 가드레일 검증 실행
  4. 문제 발견 시:
     a. 경미: 로그만 기록
     b. 중간: 사용자에게 수정 알림 + 재생성 권고
     c. 심각: 해당 응답 플래그 + 관리자 리뷰

예외 (실시간 가드레일 필요한 경우):
  - 면접 답변 평가 (즉각 피드백이 UX 핵심)
  - 이력서 고도화 (재생성이 필요한 경우)
```

| 기능 | 에이전트 패턴 | 모델 | 루프 | 가드레일 |
